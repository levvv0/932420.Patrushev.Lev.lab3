1. Навигационное меню на `Flexbox`

К элементу `<nav>` применены `display: flex`, `flex-wrap: wrap` и `gap: 12px`. На широком экране ссылки располагаются горизонтально и переносятся, если ширины недостаточно. На мобильном экране меню становится вертикальным через `flex-direction: column`.
Ссылки ведут к разделам «Навыки», «Проекты», «Технологии», «Прогнозы» и «Обратная связь». Атрибут `aria-label` задаёт доступное название навигации.

2. `Flex`-карточки «Технологии будущего»

Контейнер `.technologies` использует `Flexbox` с переносом строк и расстоянием 16 px между карточками. Внутри находятся четыре элемента `<article class="card technology-card">`.
В каждой карточке есть заголовок `<h3>`, описание и год прогноза в элементе `<time>`. Тег `<article>` выбран, потому что карточка является самостоятельным описанием одной технологии.
На широком экране ширина карточки задаётся через `flex: 0 0 calc((100% - 48px) / 4)`: из доступной ширины вычитаются три промежутка по 16 px, остальное делится на четыре. На планшете используются две карточки в ряд, на телефоне — одна.

3. `Grid`-дашборд «Прогнозы по сферам»

Контейнер `.forecast-grid` использует `display: grid`, `grid-template-columns` и `gap: 16px`. В нём находятся ровно три блока `<article class="forecast-card">`.
На широком экране используется `repeat(3, minmax(0, 1fr))`: три равные колонки. На планшете — две колонки, на телефоне — одна. Функция `minmax(0, 1fr)` позволяет колонкам сжиматься, не расширяя страницу из-за длинного содержимого.
Общее условие упоминает 2–3 колонки и 2–3 строки, а индивидуальный вариант задаёт три блока и адаптивность 1/2/3. В работе выбран приоритет индивидуального варианта: на широком экране три блока занимают одну строку, на планшете — две строки, на телефоне — три. Дополнительные пустые блоки и искусственные строки не добавлены.

4. Выделение ключевых слов

В каждом прогнозе используется семантический тег `<mark>`: выделены выражения «ранняя диагностика», «беспилотный транспорт» и «термоядерные станции». Для выделения задан тёмный текст на голубом фоне.

5. Адаптивность

В `HTML` добавлен `<meta name="viewport" content="width=device-width, initial-scale=1">`. В `CSS` предусмотрены два медиа-запроса: `max-width: 1023px` и `max-width: 599px`.
На планшетах боковая панель становится обычным блоком, а форма занимает доступную ширину. На телефонах изображение с классом `.profile-photo` возвращается в обычный поток документа через `position: static`, отменяется зарезервированное для него место справа, уменьшаются отступы. Отдельный класс не позволяет правилам позиционирования повлиять на другие изображения, если они появятся на странице.

Фиксированная ширина формы 700 px из второй работы заменена гибким размером. Поля не выходят за границы контейнера. Для длинных слов предусмотрен перенос через `overflow-wrap: anywhere`; для карточек — `min-width: 0`. Поле сообщения разрешено растягивать только вертикально. Горизонтальное переполнение всей страницы не скрывается свойством `overflow-x: hidden`.

6. Доступность

Сохранены `lang="ru"`, семантические теги страницы и описание изображения в `alt`. Карточки имеют теги `<article>` и собственные заголовки. Поля формы связаны с подписями `<label>` через совпадающие `for` и `id`. Подсказки `placeholder` дополняют подписи.

Ссылки, поля и кнопка доступны с клавиатуры. При фокусе появляется заметная розовая рамка. Глитч-эффект декоративный: содержимое доступно без наведения. Для формы серверная обработка не реализована, сообщения автору не доставляются.
